2. Introduction

This project is an interactive e-book for STA258: Statistics with Applied Probability at the University of Toronto Mississauga, built with R Bookdown (gitbook format).

The rendered book is hosted on GitHub Pages at:
https://nishanmudalige.github.io/STA258_Book/

Key features of this book:

  • Exercise boxes with collapsible hints and answers (custom HTML/CSS)
  • webR cells — live, in-browser R sessions students run without installing anything
  • Interactive Plotly apps for distribution calculators and simulations (Chapter 4)
  • Output goes to the docs/ folder, which GitHub Pages serves directly

3. How to Use This Help File

This document is intended for future maintainers and professors who want to update the STA258 book, understand what was customized, or troubleshoot a broken feature. It explains the non-obvious decisions made during development so you do not have to re-discover them from scratch. In particular, read §9 before touching webR, read §12 before touching Git, and read the Common Errors section (§13) before assuming something is broken.

Quick Guide: If You Want to Update the Book

  1. Edit the source .Rmd file in Chapters/ — never edit files inside docs/.
  2. Render locally using the command in §6 (Rendering).
  3. Test in Chrome or Firefox — Safari blocks webR on local file:// URLs (see §13).
  4. Commit both the .Rmd source and the docs/ output.
  5. Push to GitHub — GitHub Pages will update within a minute.
  6. After any merge, confirm _output.yml still has in_header: webr-exercises.html — this line is sometimes lost in merge conflicts.

Where to Edit What

If you want to…Edit this file
Add or change chapter text, examples, or theory Chapters/XX-ChapterName.Rmd (body, above the Exercises section)
Add or edit written exercises (with hints and answers) Chapters/XX-ChapterName.Rmd (Exercises section, raw HTML exercise-box divs)
Add or edit webR interactive coding exercises Chapters/XX-ChapterName.Rmd (Exercises section, raw HTML webr-exercise divs — see §8 for the template)
Change fonts, colours, spacing, or layout of the book style.css
Change the chapter order, book title, or output folder _bookdown.yml
Change which CSS files load or which files are injected in the header _output.yml
Fix or update how webR exercise cells work (buttons, output, plots) webr-exercises.html (the CSS + JavaScript that powers all webR cells)

Book_Files vs Book_files — case matters on GitHub. GitHub Pages runs on Linux, which is case-sensitive. Book_Files/ (capital F) and Book_files/ (lowercase f) are two different folders on GitHub even though macOS treats them as the same. The rendered website uses docs/Book_files/figure-html/ (lowercase f) — this is what bookdown generates and what every HTML page references. Do not manually delete or rename docs/Book_files/ unless you have first confirmed that no rendered HTML file references it.

5. Important YML Files

Two YAML configuration files control how the book is built and deployed. You must understand both before making structural changes to the project.

_bookdown.yml

Controls the book's build settings — the chapter order, the output folder, and the merged filename. The most important lines are: 

book_filename: "Book"       # merged R Markdown filename (internal)
output_dir: "docs"          # rendered HTML goes into docs/
rmd_files:                  # explicit chapter order
  - "index.Rmd"
  - "Chapters/01-Introduction.Rmd"
  - "Chapters/02-An_Introduction_to_R.Rmd"
  - ...
  • To add a new chapter, add its path to rmd_files in the correct position.
  • To render only one chapter for testing, comment out the others with # — this speeds up rendering significantly.
  • The output_dir: "docs" line is what makes GitHub Pages work — it tells bookdown to write all output into docs/, which is the folder GitHub Pages is configured to serve.

_output.yml

Controls the gitbook appearance and what extra files are loaded into each page's <head>. The most critical lines for this project are: 

bookdown::gitbook:
  css: [style.css]
  includes:
    in_header: webr-exercises.html
  • css: [style.css] — loads the main stylesheet on every page.
  • in_header: webr-exercises.html — injects the webR CSS and JavaScript into every rendered page. If this line is missing or removed, all webR exercise cells will stop working. Always check this line after a git merge.
Why output_dir: "docs" and in_header: webr-exercises.html must not be removed: The GitHub Pages deployment for this repository is configured to serve files from the docs/ folder. The output_dir: "docs" line makes bookdown write there; without it the output goes to _book/ and the live website will not update. Similarly, removing in_header: webr-exercises.html silently breaks all interactive R exercises — no error is shown at render time.

6. Rendering the Book

The system pandoc may not work. Use the pandoc bundled with RStudio instead. Run this command from the STA258_Book/ root directory: 

PANDOC=/Applications/RStudio.app/Contents/Resources/app/quarto/bin/tools/aarch64/pandoc \
  Rscript -e '
    rmarkdown::find_pandoc(
      dir="/Applications/RStudio.app/Contents/Resources/app/quarto/bin/tools/aarch64"
    )
    bookdown::render_book("index.Rmd", output_format="bookdown::gitbook", quiet=TRUE)
  '

Or from inside RStudio console:

bookdown::render_book("index.Rmd", output_format = "bookdown::gitbook")

The output goes to docs/. After rendering, commit and push to GitHub — Pages will update automatically within a minute.

7. Exercise Box Structure

All exercises use a consistent HTML structure. The three components — question box, hint, and answer — are written directly in the .Rmd file as raw HTML.

Question Box

<div class="exercise-box">
<div class="exercise-label">Question 1</div>
Your question text here. You can use **Markdown**, $\LaTeX$ math, and R code chunks.

(a) Part a...
(b) Part b...
</div>

Hint (collapsible)

<details data-type="hint">
<summary>💡 Hint</summary>
<div class="content">
- Bullet point hint here.
- Another hint.
</div>
</details>

Answer (collapsible)

<details data-type="answer">
<summary>✅ Answer</summary>
<div class="content">
**(a)** Full solution with working...

$$\bar{x} = \frac{\sum x_i}{n} = \frac{35}{7} = 5$$
</div>
</details>
Rule: Never modify the original chapter body content (the textbook exposition before the Exercises section). Only add or edit content in the Exercises section at the bottom of each chapter file.

8. webR Interactive Exercise Structure

How webR works

webR runs a full R engine inside the browser using WebAssembly — no server needed. The CSS and JavaScript that power all webR cells are loaded from a single file: 

webr-exercises.html

This file is injected into every page's <head> via _output.yml: 

bookdown::gitbook:
  css: [style.css]
  includes:
    in_header: webr-exercises.html
If webR stops working after a merge: check that _output.yml still has the includes: in_header: webr-exercises.html lines — they can be accidentally removed during a merge conflict.

Editor choice — native <textarea>

The final implementation uses a native HTML <textarea class="webr-editor"> as the code input area. It does not use CodeMirror, Ace editor, or Quarto live-runtime. This choice was intentional for stability inside bookdown/gitbook:

  • CodeMirror 5 caused cursor/text alignment bugs inside the bookdown/gitbook CSS environment that could not be fixed with CSS overrides. (See §13 for details.)
  • Quarto live-runtime (live-runtime.js) requires the full Quarto OJS environment and cannot be dropped into bookdown by simply loading the script. (See §13.)
  • A plain <textarea> has no line numbers or syntax highlighting, but it is completely stable, has no cursor issues, and is easy to maintain.

webR cell HTML template

Place a webR cell inside (or after) an exercise box. The <textarea> holds the starter code students will see. Include a <canvas> element only if the question produces a plot. The textarea auto-resizes to fit its content. 

<div class="webr-exercise">
<div class="webr-exercise-header">Exercise</div>
<textarea class="webr-editor" rows="5">x <- c(1, 2, 3, 4, 5)
# (a) Compute the mean
mean(x)
# (b) Compute the standard deviation
sd(x)
</textarea>
<div class="webr-controls">
  <button class="webr-run-btn" disabled>▶ Run</button>
  <button class="webr-reset-btn">↺ Reset</button>
</div>
<div class="webr-output-area"></div>
<div class="webr-canvas-area"><canvas></canvas></div>
</div>

Key rules for webR exercises

  • Use only R syntax taught in Chapter 2: c(), mean(), sd(), var(), sum(), sort(), hist(), boxplot(), summary(), IQR(), etc.
  • Do not use cat() — use separate function calls on individual lines instead.
  • Use hist() and boxplot() (base R) — not ggplot2 — in Chapter 3 exercises.
  • For Chapter 5–6 exercises: qnorm(), qt(), t.test(), prop.test(), pnorm(), pt() are appropriate.
  • The scaffold (starter code in the textarea) should be incomplete — students fill in the blanks.
  • The Answer section must contain the complete runnable R code.
  • Omit the <canvas> div if the question has no plot output.

9. What We Built / Custom Changes Made

This section documents the non-obvious changes made to the project that are not derivable from reading a standard bookdown tutorial. This is the "what did you guys do" section the professor can consult before making updates.

webR in bookdown — how we got it to work

Bookdown does not natively support webR. The standard approach (used in Quarto or standalone HTML) does not plug in directly. To make it work we:

  1. Created webr-exercises.html from scratch. This file contains all CSS styling for the exercise cards, buttons, output area, and canvas (for plots), plus a <script type="module"> block that:
    • Imports WebR from the CDN: https://webr.r-wasm.org/latest/webr.mjs
    • Initialises the R engine on page load
    • Installs ggplot2 on first visit (~30 s, cached after that)
    • Wires up Run and Reset buttons for every .webr-exercise div on the page
    • Reads code directly from textarea.value when Run is clicked
    • Auto-resizes the textarea to fit the starter code height on load
    • Renders text output into .webr-output-area
    • Renders plot output onto the <canvas> inside .webr-canvas-area when present
  2. Added in_header to _output.yml so that webr-exercises.html is injected into the <head> of every rendered HTML page: 
    bookdown::gitbook:
  css: [style.css]
  includes:
    in_header: webr-exercises.html
  3. Wrote the webR cell HTML directly in each .Rmd file (see §8 for the template). Because bookdown passes raw HTML through to the output, this works without any special plugin.
Editor: The code input area is a styled native <textarea>. We deliberately do not use CodeMirror or Ace — see §13 for why. Do not add a third-party code editor library back without reading the known issues section first.

Exercise box CSS

The exercise boxes, collapsible hints, and collapsible answers are styled via style.css and box.css. The collapsible behaviour uses the native HTML <details>/<summary> elements — no JavaScript needed. The data-type="hint" and data-type="answer" attributes on <details> trigger different colours via CSS attribute selectors.

Datasets

We are not including local CSV files. All datasets used in exercises are either:

  • Hard-coded inline as c(...) vectors in the exercise text, or
  • Built-in R datasets (e.g., mtcars, faithful).

This avoids file-path issues when the book runs in the browser via webR or is served from GitHub Pages.

RGL removed

An early version of the book used the rgl package for 3D plots. It was removed because of version conflicts — rgl requires specific system libraries and caused render failures on some machines. If you see any leftover rgl references in the code, they can be deleted.

12. GitHub Workflow

The repository is at: github.com/nishanmudalige/STA258_Book

Branch strategy

  • Work on your own branch (e.g., janice-ch5), not directly on main.
  • Only merge to main when a chapter is ready — merging too early causes conflicts.
  • After merging, always check that _output.yml still contains in_header: webr-exercises.html.

Typical workflow

# Create a new branch
git checkout -b janice-ch6

# Edit .Rmd files, then render to check output
bookdown::render_book("index.Rmd", output_format = "bookdown::gitbook")

# Stage, commit, push
git add Chapters/06-Hypothesis_Tests.Rmd docs/
git commit -m "Add Ch6 hypothesis test exercises with webR"
git push origin janice-ch6

# Open a pull request on GitHub, then merge into main
Hidden file (.nojekyll): The docs/ folder must contain an empty file called .nojekyll for GitHub Pages to serve images correctly. This file is hidden on Mac (starts with a dot). Do not delete it.

13. Common Errors & Known Issues

⚠️ Safari: Run button does not work locally

Known issue. When you open the rendered HTML files directly from your local docs/ folder in Safari, the webR Run button does not respond. This is a browser security restriction on local file:// URLs — Safari blocks the WebAssembly module from loading.

Workaround: webR works correctly once the book is pushed to GitHub Pages. For local testing, use Chrome or Firefox instead of Safari.

webR not loading / Run button stays grey (on GitHub Pages)

Check that _output.yml still has:

bookdown::gitbook:
  css: [style.css]
  includes:
    in_header: webr-exercises.html

This line is sometimes silently dropped during a git merge conflict. Re-add it and re-render. This has happened before — always double-check after merging.

Render warnings that can be ignored

The following warnings appear during every render and are safe to ignore:

[WARNING] Citeproc: citation BryanSu426 not found
[WARNING] Citeproc: citation chimera1001 not found
[WARNING] Citeproc: citation nishanmudalige not found
[WARNING] Citeproc: citation nurlanaalili not found
[WARNING] Deprecated: --highlight-style. Use --syntax-highlighting instead.
Warning in snapshot3d(...): webshot = TRUE requires the webshot2 package and Chrome browser

None of these affect the output. The citation warnings are for references not yet in the .bib file; the snapshot warning is from an rgl leftover that does not affect HTML output.

Pandoc not found when rendering

Use the full PANDOC path pointing to RStudio's bundled pandoc:

PANDOC=/Applications/RStudio.app/Contents/Resources/app/quarto/bin/tools/aarch64/pandoc \
  Rscript -e 'bookdown::render_book("index.Rmd", "bookdown::gitbook")'

Images not showing on GitHub Pages

Make sure docs/.nojekyll exists — it must be an empty file with exactly that name. Without it, Jekyll (GitHub's default processor) ignores files in folders starting with underscore, causing images to disappear. 

touch docs/.nojekyll
git add docs/.nojekyll
git commit -m "Restore .nojekyll"
git push

Merge conflict in docs/ folder

The docs/ folder is generated — never edit it by hand. If there is a merge conflict inside docs/, accept either version, then re-render the book to regenerate docs/ cleanly from source.

R chunk label conflict

Every ```{r label} chunk label must be unique across the entire book. If you copy a chunk from one chapter to another, rename its label. Duplicate labels cause the render to fail: Error in parse_block: duplicate label 'xyz'.

RGL / 3D plot errors

The rgl package was removed from this project due to version conflicts. If you see errors mentioning rgl, rglWebGL, or CanvasMatrix, delete the relevant code chunk — rgl is no longer used.

webR editor cursor / text misalignment

If a code editor inside a webR exercise shows the cursor in the wrong position, typed text that does not line up with the background rows, or the cursor floating above or below the current line — this is a browser/CSS rendering issue, not an RStudio or VS Code issue. Switching editors will not fix it because the bug happens in the browser after the book has been rendered.

History of the problem in this project:

  • An earlier version used CodeMirror 5 (loaded from cdnjs) as the code editor.
  • CodeMirror 5's JavaScript positions the cursor by measuring line height at initialisation time. When the bookdown/gitbook CSS overrides line-height on CodeMirror elements, the cursor position calculated by JS and the lines rendered by CSS become inconsistent — producing the visible misalignment.
  • Multiple CSS workarounds were attempted (line-height: 17px, height: 18px !important on .CodeMirror-cursor, multiple cm.refresh() calls) — none reliably fixed the issue across browsers.
  • The final decision was to replace CodeMirror with a native <textarea>. The browser's built-in textarea cursor is always correct.
Do not reintroduce CodeMirror or Ace unless the root cause (line-height conflict with the gitbook CSS) is properly resolved. Do not attempt to fix cursor alignment by adding CSS hacks such as .CodeMirror-cursor { transform: translateY(...) } or .CodeMirror-cursor { top: ... } — these do not address the underlying measurement inconsistency and will break on other browsers or screen sizes.

Do not directly replace bookdown webR with Quarto live-runtime

The Quarto live-html format (powered by the r-wasm/quarto-live extension and its live-runtime.js) produces clean, well-aligned webR exercise cells. However, you cannot drop it into this bookdown project by only loading live-runtime.css and live-runtime.js.

Quarto live-runtime requires:

  • A specific generated HTML structure: <div class="exercise-cell"> divs with corresponding <script type="webr-N-contents"> blocks containing base64-encoded JSON payloads
  • The full Quarto OJS runtime environment for initialisation
  • Additional webr-data attributes and OJS variable bindings that Quarto generates at compile time from {webr} code chunks

The current bookdown implementation uses .webr-exercise divs, <textarea class="webr-editor">, and custom JavaScript in webr-exercises.html. These are completely different structures.

If you only load live-runtime CSS/JS without converting the HTML structure, the editable R exercise cells will disappear from the page — the textarea will be hidden but nothing will replace it. This was tested and confirmed during development. If you want to migrate to Quarto live-runtime in the future, you must also convert all .Rmd exercise HTML to the exercise-cell format AND provide the full Quarto OJS runtime context.

Cannot switch branches because docs/ has generated changes

The docs/ folder is generated output. If Git refuses to switch branches because files in docs/ would be overwritten, you have two options:

Option A — discard the generated changes and switch:

git restore docs/
git clean -fd docs/
git switch main
git pull

Option B — commit the generated output first:

git add docs/
git commit -m "Render book output"
git switch main
git pull
Never manually edit files inside docs/ — always edit source .Rmd files and re-render. Any manual edits in docs/ will be overwritten on the next render.
